# ISSUE-002: 2026-09 분류 정확도 미흡 (LLM-as-judge 기준 20%)

## 이슈 요약
2026-09 월 데이터에 대해 LLM-as-judge 검증 결과 5개 샘플 중 1개만 정확으로 판정(20%).
2026-08은 동일 조건에서 60%였으나 두 달 모두 기준치(80%) 미달.

## 재현 조건
```
npx ts-node src/index.ts validate --month 2026-09
```
- 모델: llama3.1:8b
- 샘플 수: 5개 (Fisher-Yates 무작위)
- 검증 방식: LLM-as-judge (동일 모델이 분류 + 검증)

## 원인 분석
1. **동일 모델 편향 (Circular validation)**: 분류와 검증을 같은 모델(llama3.1:8b)이 수행. judge가 자신의 분류 스타일과 다른 기준으로 평가할 때 부정확 판정이 과다하게 나올 수 있음.
2. **태그 세분화 불일치**: 분류 프롬프트는 "짧은 한국어 태그 최대 3개"를 요구하지만, judge는 더 세부적인 태그(예: "슬라이딩 윈도우", "로직 오류")를 기대하는 경향이 있음.
3. **샘플 크기 한계**: 5개 샘플은 통계적으로 신뢰도가 낮음. 한 건의 판정이 20%p를 좌우.
4. **단답형 대화 불리**: 짧은 대화(token이 적은)는 맥락이 부족해 judge가 "더 많은 태그가 필요하다"고 오판.

## 적용한 해결책
현재 미적용 — 정확도 수치를 DB에 기록하여 추이 추적 가능 상태로 전환.

## 개선 방안 (우선순위 순)
1. **샘플 수 확대**: `--sample-size 10` 으로 통계 신뢰도 향상
2. **judge 프롬프트 개선**: "태그가 대화의 핵심 주제를 포함하면 정확으로 판정. 세부 태그 부재는 부정확이 아님"을 명시
3. **이종 모델 judge 도입**: 2단계에서 Claude API / GPT-4를 judge로 사용해 circular validation 해소
4. **분류 프롬프트 튜닝**: 짧은 대화에 대해 태그를 1~2개로 줄이도록 조건 추가
